---
name: ux-product-design
description: Design software-product flows and UI behavior with clear states, design-system reuse, responsive behavior, accessibility, and testable UX acceptance notes.
---

Start from user goal and acceptance criteria.
Define:
- entry points and happy path;
- alternate/error/empty/loading/success/permission states;
- navigation and information architecture;
- keyboard/focus behavior;
- responsive expectations;
- component/design-system reuse;
- content/microcopy requirements when material;
- accessibility constraints (WCAG 2.2 AA baseline unless stricter product rule exists).

Avoid inventing new visual patterns when an existing design-system component solves the need.
Persist durable UX decisions.
