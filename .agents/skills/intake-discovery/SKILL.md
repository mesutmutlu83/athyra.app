---
name: intake-discovery
description: Turn a raw feature, bug, refactor, UX, architecture, or operations request into a clear problem statement and determine whether clarification or a human decision is required before work starts.
---

Read existing product/system docs and relevant code first.

Determine:
- whether users, tenant/workspace context, RBAC/permissions, ownership, invitations, or delegated admin are affected;
- whether an existing shared foundation should be reused;
- request class;
- objective and user/business outcome;
- current behavior/problem;
- target user/persona;
- desired observable behavior;
- scope/out-of-scope;
- constraints;
- relevant edge cases;
- data/security/integration/migration impact;
- non-functional needs;
- whether the Human Decision Gate applies.

Ask only material missing questions and group them into one batch.
Do not ask the user to decide ordinary internal implementation details.
Do not begin implementation until the task is sufficiently understood.
