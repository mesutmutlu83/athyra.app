# Design System

No implemented component or token system exists in the repository yet.

Required product semantics independent of visual style:

- Always distinguish planned, imported, user-reported, and derived information.
- Show freshness, source, uncertainty, support level, and unavailable/unknown states.
- Provide explicit loading, empty, error, offline, permission-denied, stale, conflict, and retry states.
- Keep athlete, coach, admin, support, and finance workspaces visually and semantically distinct.
- Never present an unverified payment, sync, permission, health value, or AI proposal as successful/final.
- iPhone layouts must account for iPhone 12 mini and larger/adaptive form factors.
- Admin release/configuration UI must use explicit lifecycle/status labels, accessible validation summaries, textual before/after diffs, environment/version badges, non-color-only warnings and keyboard-operable tables/relationship controls.
